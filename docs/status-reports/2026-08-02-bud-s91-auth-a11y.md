**Resume here:** **both surfaces are now axe-gated and one real defect is fixed.** The sign-in error
message rendered at **2.78:1 against the dark surface** — a serious WCAG 1.4.3 failure on shipped UI
— because `Login.module.css` referenced **`--color-danger-fg`, a token defined nowhere in the
codebase**, so it always resolved to a hard-coded light-mode red that no theme could re-point. It now
uses `--color-danger`, which tokens.css re-points under `prefers-color-scheme: dark`. **e2e 124 →
132** (+8 scans). Every new scan was proven to fail on an injected defect before being trusted, so a
green result means the scan looked. Gate green: **483 Vitest + 132 e2e**. Nothing deferred.

## 1. What landed

| Item | Notes | Source |
| ---- | ----- | ------ |
| **The defect: an error message nobody could read in dark mode** | `color: var(--color-danger-fg, #b91c1c)`. `--color-danger-fg` is **defined nowhere** — grep returns exactly one hit, this use — so the fallback was always in force: `#b91c1c` on `#14171a` = **2.78:1**, against a 4.5:1 requirement. The real token is `--color-danger` (`#b42318` light, `#f3736f` dark). Fixed to use it, **with no fallback literal**: a missing token should fail visibly rather than silently pin a colour the theme cannot reach. Checked for the same pattern repo-wide — this was the only `var(--…, #literal)` in the web source. | [`Login.module.css`](../../apps/web/src/Login.module.css) |
| **Sign-in page scans (4)** | New [`e2e/a11y-auth.spec.ts`](../../e2e/a11y-auth.spec.ts): the form and its **error state**, light and dark. A separate file rather than another block in `a11y.spec.ts` for two structural reasons — the page is only reachable *without* a session (so it must opt out of global-setup's shared `storageState`), and `a11y.spec.ts` has a file-wide `afterEach` that navigates to the dashboard, which an unauthenticated page cannot do. Same reasoning that already isolates `auth.spec.ts`. | `e2e/a11y-auth.spec.ts` |
| **User-management scans (4)** | Added to [`e2e/a11y.spec.ts`](../../e2e/a11y.spec.ts) in the existing describe-block style: the users **table** and the expanded **add-member form**, light and dark. The suite runs as the admin, so the table always has a real row and never renders its empty state or skeleton. | `e2e/a11y.spec.ts` |
| **The error-state scans cannot lock out the suite** | Deliberately failing a sign-in touches the `BUD-S89` throttle, which is keyed on **(client IP + username)** with a 5-fail / 15-minute lockout. Each error scan uses a **unique, non-existent username**, so it burns one failure against a key nothing else uses and can never count against the shared admin the serial suite depends on. Verified the key construction before writing the tests rather than after. | `server.ts:233` |

## 4. The `BUD-S87` / `BUD-S88` accessibility record, corrected

History is not being rewritten — those reports stand as written. What follows is the correction:

- **`BUD-S87`** (auth core + login) shipped the `/login` page with **no accessibility line in its
  Definition of Done at all**. The surface was never scanned, and the omission was not visible as an
  omission.
- **`BUD-S88`** (roles + user management) stated that *"the a11y axe scan now also covers the
  admin-only Users nav entry."* That is true and was never the claim that mattered: the **page behind
  the entry** — a data table plus a three-field form — was not covered.

  scan suite is not coverage**; it only covers the surfaces someone added to it. The gap survived two
  slice reviews and surfaced only when a human-facing PR checklist was filled in on 2026-08-02.
- The defect this concealed was real and serious-impact, not theoretical.

Logged as [`KIT_FEEDBACK` **K41**](../KIT_FEEDBACK.md) so the checklist stops being satisfiable

## 6. Commands & gotchas (cold-start)

```sh
npm install
npm run typecheck && npm run lint && npm run format && npm run docs:check
npx vitest run                                  # 483
npx playwright test                             # 132 — needs :3001 and :5173 free, colima STOPPED
npx playwright test e2e/a11y-auth.spec.ts       # the 4 sign-in scans alone (~5 s)
npx playwright test e2e/a11y.spec.ts -g "user management"   # the 4 users scans alone
```

- **A new axe scan is not trustworthy until it has failed once.** Inject a defect, watch it go red,
  revert with `git checkout`. Three of these four surfaces passed first try; without that check the
  slice would have "closed" a gap it had only papered over.
- **`--color-danger` is the danger token.** `--color-danger-fg` does not exist. Do not give `var()` a
  hard-coded colour fallback — it survives every theme change silently.
- **Unauthenticated specs need their own file**, not just their own `test.use`: `a11y.spec.ts`'s
  `afterEach` navigates to the dashboard and a signed-out page cannot.
- **Failing a login on purpose is throttled** on (IP + username), 5 fails / 15 min. Use a unique
  non-existent username so the real admin's budget is never touched.
- **`colima stop` before e2e**; never run the deploy harness and e2e at once.
- The API is at **`/api`**; `VITE_API_BASE_URL` is the **origin only**.
